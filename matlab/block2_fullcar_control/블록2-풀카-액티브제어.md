## 구현 방식

- **Simulink는 물리 부품별 서브시스템**으로 구현 (2026-11-03 변경, 설계안 v0.8의 State-Space 블록 방식 대체):
  Load Transfer · Corner FL/FR/RL/RR(스프링·댐퍼·액추에이터·스태빌라이저 힘, 비현가 질량, **단방향 타이어 접촉**)
  · Anti-roll Bar · Sprung Body · Controller. 상태는 적분기 출력이고 힘은 상태에서만 계산하므로 대수루프가 없다
  (cae5 문제 회피, `AlgebraicLoopMsg = error`로 강제). 변경 이유: 모델에서 물리가 보이고(발표용), 타이어 이탈을
  `max(0, ·)` 하나로 다룰 수 있음.
- LQR 설계용 `A, B`는 `build_state_space.m`이 따로 만든다. 두 모델의 일치는 `linmod` 선형화로 확인한다
  (상대오차 1e-16) — 블록 다이어그램과 손으로 유도한 행렬을 독립적으로 교차 검증하는 셈.
- 상태: 7DOF → 14개(변위+속도), 액추에이터 1차 지연 포함 시 +4
- 입력 10개: 액추에이터 힘 4개(FL,FR,RL,RR, 휠 기준) + 노면 변위 4개 + ax, ay (블록 1 출력 그대로).
  **스프링 강성과 액추에이터 포화 한계는 앞뒤를 따로 둔다.**
  후륜 노면은 τ=L/v 대신 거리 s−b로 넣어 가감속 중에도 정확하다.
- 수평 하중 얹기(함정 1 대응): Load Transfer에서 pitch 모멘트 `M_θ = −m_s*ax*h_cg`, roll 모멘트 `M_φ = m_s*ay*h_cg`를 차체에 인가.
  M_θ의 부호는 ISO 8855에서 θ(+) = 노즈 다운이기 때문 (제동 ax<0 → 노즈 다운).
  타이어 Fx,i/Fy,i는 Fz,i 비례 분배. anti-dive·롤센터 효과는 무시(가정으로 명시).
- 제어기 4종: Passive / Skyhook(기준선) / LQR(승차감·접지 가중치) / 위치 스케줄 LQR (→ 블록 6)

## 액추에이터 현실성 (D15)

- 포화 + 1차 지연(대역폭) 반영. 기준값은 양산 액티브 서스펜션 공개 수치(**Audi A8: 포화 약 3.7kN·뒤 약
  3.3kN, 대역폭 0–6Hz, 힘 증가율 16kN/s에서 출발[R17]**) — 이 값이 액추에이터 기준인지 휠 기준인지 **출처에서
  확인해야 함(D15)**, 포화는 p별 모선비로 휠 기준 환산해 적용(4.3절, 아래 참고).

## 프런트 마운트 위치 p (v0.8, 블록 3·4a와 공유하는 설계 변수)

마운트가 안쪽일수록 모선비 MR이 작아져 같은 휠 힘에 필요한 액추에이터 힘이 커진다
(`F_act = F_wheel/MR`, 스프링 강성 환산은 ∝ 1/MR²). **포화·스트로크·속도 한계는 액추에이터 기준이므로**
휠 기준으로 환산해 이 블록에 적용한다: `F_sat,wheel = MR(p) * F_sat,act`, 휠 스트로크·속도 한계 =
액추에이터 한계 / MR(p). 따라서 **블록 2는 p마다 다시 실행**한다 (블록 3이 같은 MR(p)로 액추에이터 실제
힘·마운트 하중을 환산). p의 3수준 값 자체는 D16에서 확정.

## 출력 → I1

코너별 휠센터력 `(Fx,Fy,Fz)_i`, 액추에이터 힘 `F_act,i`, **스프링·댐퍼 힘 4개(v0.4 추가)**, 차체 가속도,
서스펜션 스트로크, 시나리오 태그(블록 3 입력).
