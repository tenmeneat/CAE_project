# 2026-11-03 · 블록 2 제어기 설계 (Skyhook·LQR)와 I1 내보내기

← [블록 2 풀카 Passive](2026-11-03-블록2-풀카-Passive.md) · [05-작업기록](../05-작업기록.md)

## 한 일

- 모델을 **노면 추세 좌표계**로 옮겼다. 고저는 변위 입력에서 빼고 바퀴 위치의 추세 수직 가속도
  z̈_ref = v²·z'' + ax·z'로 넣는다 (관성력 −M·q̈_ref). Simulink의 Load Transfer는 Inertial Loads(이득 `veh.Gin`)가 됐다.
- 3축 지표 `fullcar_metrics`: 운전석 절대 수직 가속도의 ISO 2631-1 Wk 가중 RMS(`iso2631_wk`), 코너별 타이어 동하중
  RMS·이탈, 스트로크, 액추에이터 RMS·피크 힘·평균 출력.
- `controller_skyhook`, `controller_lqr`, `compare_controllers`. 모든 제어기가 `F_act = −Kfb·[x; w]` (4×22) 하나의 블록.
- I1 내보내기 `export_i1`: Spa A/B × passive·skyhook·lqr 6개 파일. Fx는 구동 시 후륜만, 스프링 힘은 정적 하중 포함.
  처음엔 비현가 가속도를 수치미분해 너클 평형 잔차가 73 N RMS였는데(1 ms로 200 Hz 노면 성분을 못 잡음), Simulink 내부
  가속도를 로깅해 잔차 1e-10 N 수준으로 맞췄다. 마찰 사용률 초과 구간은 자르지 않고 `mu_use`로 표시.

## 경과와 판단

- 처음 Spa에서 Passive 차체의 절대 수직속도를 보니 최대 6 m/s였다 (언덕 추종). Skyhook을 절대 좌표로 걸면
  10–15 kN이 나와서, 실차처럼 하이패스한 양에만 피드백하도록 좌표계를 바꿨다. 추세 가속도를 두 번 적분하면 고저와
  RMS 2–4 cm로 일치한다.
- 첫 LQR은 타이어 변형 대신 zu를 벌했다 (노면 r = 0 가정). 결과는 10–40 kN, 스트로크 0.4–0.7 m, 접지는 Passive보다
  나빴다 — 바퀴가 노면을 따라가는 것까지 벌했기 때문. 노면 요철을 ISO 8608 1차 필터로 증강해 고쳤다.
- 그래도 스트로크가 수백 mm였다. LQR이 노면만 보고 서스펜션을 무르게 만든 탓이라 ax, ay, z̈_ref도 느린 외란 상태로
  증강했다 → 스트로크 ±35–55 mm, 가속도 피드포워드 이득이 생김 (양산 액티브의 롤·피치 보상과 같은 구조).
  타이어 동하중 비용은 지표와 같게 Passive 준정적 분배를 빼서 정의했다.
- Skyhook ζ_sky는 시나리오 B 접지를 Passive보다 나쁘게 하지 않는 최대값 0.3으로 정했다.
- ISO 2631-1 Wk 필터는 표준 표 값과 1% 이내로 맞는 것을 테스트로 확인.
